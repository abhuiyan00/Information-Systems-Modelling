14. ASPECT-ORIENTED PROGRAMMING (AOP)
--------------------------------------------------------------------------------

14.1  What AOP is and why

  AOP separates cross-cutting concerns (logging, auditing, performance
  monitoring) from business logic without modifying existing classes.
  A concern is "cross-cutting" when it spans many unrelated classes â€”
  logging every service call is the canonical example.

  Spring AOP uses runtime CGLIB proxies (no bytecode weaving required).
  Full AspectJ adds compile-time / load-time weaving and supports method
  calls, field access, and constructors â€” Spring AOP only intercepts
  method calls on Spring-managed beans.

  Key AOP vocabulary:
    Join point    A point in execution where advice can be inserted.
                  In Spring AOP, always a method execution.
    Pointcut      A predicate that matches one or more join points
                  (expressed with AspectJ pointcut expressions).
    Advice        Code that runs at a matched join point.
    Aspect        A class annotated @Aspect that groups pointcuts + advice.
    Weaving       Linking aspects into application classes.
                  Spring: runtime proxy weaving.  AspectJ: compile-time.

14.2  Advice types

  @Before           Runs before the method.  Cannot prevent execution
                    (throw an exception to abort).
  @AfterReturning   Runs after normal return.  Can inspect the return value
                    via the `returning` attribute.
  @AfterThrowing    Runs when the method throws.  Can inspect the exception
                    via `throwing`; does NOT suppress it.
  @After            Runs after either normal return OR exception ("finally").
  @Around           Wraps the method.  Must call pjp.proceed() to invoke it.
                    Most powerful â€” can modify args, return value, or skip
                    the call entirely.

14.4  LoggingAspect  (LoggingAspect.java)

  Pointcut:  execution(public * pl.edu.pwr.tkubik.ism.service.*Impl.*(..))
  Matches all public methods of every *Impl service class (BuildServiceImpl,
  UserServiceImpl, etc.).  AnalyticsService has no Impl suffix â€” excluded.

  @Before         â†’ DEBUG "[AOP] â†’ ClassName.method() args=N"
  @AfterReturning â†’ DEBUG "[AOP] â† ClassName.method() OK"
  @AfterThrowing  â†’ WARN  "[AOP] âœ— ClassName.method() threw ExType: msg"

  Why:  Eliminates repetitive per-class logger boilerplate.  One aspect
  covers all 9 service impls uniformly.

14.5  PerformanceAspect  (PerformanceAspect.java + annotation/Timed.java)

  Pointcut:  @annotation(pl.edu.pwr.tkubik.ism.aspect.annotation.Timed)
  Applied to:  AnalyticsService.dashboard()  and  AnalyticsService.ai()
  Both run multi-table JDBC aggregations â€” most expensive DB operations
  in the backend.

  @Around:  records System.currentTimeMillis() before pjp.proceed(), logs
  the delta.  If >= 500 ms â†’ WARN "[AOP] SLOW ..."; otherwise DEBUG.

  Why @Around:  only advice type that can capture both before/after time in
  a single method body while still returning the original value.

  Why @Timed not class-level pointcut:  opt-in annotation avoids wrapping
  lightweight analytics methods that run sub-millisecond queries.
  (A commented example of the class-level alternative is in the file.)

14.6  SecurityAuditAspect  (SecurityAuditAspect.java)

  Two pointcuts:
    loginEndpoint()    targets  AuthController.authLoginPost(..)
    adminEndpoints()   targets  AdminController.*(..)

  @AfterReturning on login:
    Inspects the ResponseEntity HTTP status.  200 â†’ INFO "[AUDIT] LOGIN
    success email=..."; anything else â†’ WARN "[AUDIT] LOGIN failed ...".
    Extracts email from LoginRequest arg without modifying the controller.

  @After on admin:
    Fires for every AdminController call regardless of outcome (success or
    exception).  Logs "[AUDIT] ADMIN ClassName.method()" for an immutable
    audit trail.

  Why AOP instead of code in controllers:
    Controllers implement generated OpenAPI interfaces; adding audit logic
    there couples business code to observability concerns and complicates
    regeneration.  The aspect keeps controllers clean.

14.9  Adding a new aspect

  1. Create the file in  src/.../aspect/  with @Aspect + @Component.
  2. Write a named @Pointcut method (reusable, self-documenting).
  3. Add advice methods referencing the pointcut.
  4. No registration needed â€” Spring picks it up via component scan.

  Pointcut expression quick-ref:
    execution(* pkg.Class.method(..))    exact method
    execution(* pkg..*.*(..))            all in package tree
    within(pkg.Class)                    all methods of a class
    @annotation(ann)                     any method annotated with ann
    bean(beanName)                       all methods of named bean
    && / || / !                          combine expressions
