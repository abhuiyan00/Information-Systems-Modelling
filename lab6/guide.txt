================================================================================
 LAB 6 — GUIDE: run the app + produce the 3 deliverables
================================================================================

This lab is a small data-driven web app, NOT a Java/Maven project like lab4/lab5.
The semantic data lives ONCE in app/data/*.json; a zero-dependency Node app
generates both the RDFa (in the HTML body) and the JSON-LD (in <head>) from it.

There is no pom.xml. You only need Node >= 18 to run it; Python + rdflib is
optional, for the offline triple-count check.

  app/data/*.json  ->  one renderer  ->  RDFa + JSON-LD
                                     ->  dynamic server (npm run dev)
                                     ->  static export  (npm run build -> app/dist/)

--------------------------------------------------------------------------------
 THE 3 DELIVERABLES (what you hand in)
--------------------------------------------------------------------------------
 1. Short REPORT (PDF/DOC) = what was done + screenshots of verification (RDFa)
    and checking (Google / schema.org validator) + references to ontologies used.
 2. RENDERED SOURCE of the HTML pages = the generated app/dist/*.html (carry the
    RDFa + JSON-LD) + styles.css + vocabulary/mc-context.jsonld. The data +
    renderers in app/ are the source these are built from.
 3. CUSTOM ontology -> vocabulary/ontology.ttl (your mc: vocabulary).
    Do NOT hand in schema.org or any existing ontology — only mention them in
    the report.

================================================================================
 STEP 0 — REQUIREMENTS
================================================================================
 Node >= 18 (check: node --version). No `npm install` is needed — the app has
 zero dependencies. For STEP 4 only: Python 3 + rdflib (pip install rdflib).

 IntelliJ is optional, as an editor. There is no Maven import — correct.

================================================================================
 STEP 1 — GENERATE / RUN THE PAGES (deliverable 2 = the rendered source)
================================================================================
 From the app/ folder:

   cd app
   npm run build      # writes the whole static site to app/dist/
   npm run dev        # OR serve it live at http://localhost:3000/

 `npm run build` emits, into app/dist/:
   index.html         Home (WebSite + Organization + ItemList of builds)
   builds.html        Explore (CollectionPage + ItemList -> all builds)
   build-falcon.html  Build detail SHOWCASE (CreativeWork + mc:DroneBuild,
                      AggregateRating, votes, FLIGHT LOG + TELEMETRY custom
                      vocab, comments) -- use this one for the main screenshots
   build-arm.html / build-rover.html / build-glider.html   the other builds
   marketplace.html   Listings (Product + Offer + mc:MarketplaceListing)
   member-alice.html  Member (Person + mc:Builder + mc:ReputationRecord)
   member-bob.html / member-carol.html / member-dave.html  the other members
   testrun.html       Test run (Event + Place + mc:TestRun)
   styles.css, vocabulary/   copied so the export is self-contained

 Open app/dist/build-falcon.html in a browser to confirm the dark theme renders.
 View Source (Ctrl+U) to show the RDFa attributes (vocab=, typeof=, property=,
 about=, resource=, content=) and the <script type="application/ld+json"> block.
 Screenshot a chunk of that source for the report.

 TIP: each generated page opens with a "VOCAB MAP" comment that is produced by
 walking that page's graph (src/rdf/vocabmap.js) — it lists the page's schema.org
 terms, its custom mc: terms, and any CUSTOM-ONLY section (no schema.org
 equivalent). Use it to point out in the report which markup is schema.org and
 which is your vocabulary. The custom-ONLY sub-graphs are:
   build-falcon.html -> Flight Logs card + Telemetry card
   member-alice.html -> Reputation card

 BONUS (dynamic / Linked Data): with `npm run dev` running, every resource IRI is
 dereferenceable with content negotiation:
   curl -H "Accept: application/ld+json" http://localhost:3000/resource/build-falcon
   curl -H "Accept: text/html"          http://localhost:3000/resource/build-falcon  (303 -> the page)

================================================================================
 STEP 2 — VERIFICATION (RDFa)  -> screenshot for the report
================================================================================
 Tool: RDFa Play   http://rdfa.info/play/

 1. Open app/dist/build-falcon.html, Ctrl+U (View Source), select all, copy.
 2. Paste the markup into the RDFa Play editor (left).
 3. Choose the Turtle (or N-Triples) output tab.
 4. Confirm the extracted triples show:
       - mcr:build-falcon  is BOTH  schema:CreativeWork  AND  mc:DroneBuild
       - schema:name, schema:author -> mcr:user-alice, schema:aggregateRating
       - the mc:hasFlightLog / mc:hasTelemetry sub-graphs (custom vocab)
       - both comments
       - all the scattered cards attach to the ONE subject (no stray blank nodes)
         -- this proves the about="" technique works.
 5. SCREENSHOT the triples / graph panel. This is the "verification (2)" image.

 (Optional but strong: paste marketplace.html and confirm the two table cells —
  Condition + Price — feed the SAME Offer node, not two.)

================================================================================
 STEP 3 — CHECKING (Google / schema.org validator) -> screenshot for the report
================================================================================
   A. Schema Markup Validator   https://validator.schema.org/
      (best for the general schema.org graph: CreativeWork, Person, etc.)
   B. Rich Results Test         https://search.google.com/test/rich-results
      (best for Product, Event, AggregateRating types)

 For each page: paste its HTML code, confirm the items are detected with 0
 ERRORS. The custom mc: properties show up as recognised-but-unknown extra props
 — THIS IS EXPECTED (they are not schema.org terms). SCREENSHOT the result. This
 is the "checking (3)" image.

 Suggested pages: build-falcon.html (CreativeWork + AggregateRating),
 marketplace.html (Product + Offer), testrun.html (Event + Place),
 member-alice.html (Person).

================================================================================
 STEP 4 (OPTIONAL) — OFFLINE JSON-LD CHECK (extra proof for the report)
================================================================================
 Confirms the embedded JSON-LD yields real RDF triples. Needs Python + rdflib.
 From the app/ folder:

   npm run validate          # runs build, then app/scripts/validate.py

 Expected: every page parses with 0 errors; 333 triples total across the site,
 build-falcon.html = 76. Screenshot the terminal output for a third evidence
 image.

 STEP 5 — ASSEMBLE THE REPORT (deliverable 1)
================================================================================
 Make a short report (PDF or DOC). README.md contains the prose to reuse:
 1. Aim: publish the app's data as RDFa + JSON-LD, schema.org first, custom
    vocabulary where schema.org has no term.
 2. Why server-side: the real app is Angular (client-side), so a crawler sees
    only <app-root>. The app renders the data server-side and exports static
    snapshots — what an SSR build would emit for a bot. (README section intro.)
 3. The schema.org <-> custom mc: mapping (README section 3).
 4. The scattered-<div> @about technique (README section 4).
 5. SCREENSHOTS: rendered pages (Step 1); RDFa Play triples = VERIFICATION (2);
    schema/Google validator 0 errors = CHECKING (3); (optional) rdflib counts.
 6. ONTOLOGY REFERENCES:
       - schema.org   https://schema.org/   (EXISTING — referenced, NOT delivered)
       - XSD          http://www.w3.org/2001/XMLSchema#   (existing)
       - Custom mc:   http://modellingclub.local/ontology#  -> DELIVERED as
                      vocabulary/ontology.ttl (originates from lab5).

 Save the report as e.g.  lab6-report.pdf  in this folder.
